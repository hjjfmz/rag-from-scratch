# PostgreSQL / Qdrant / Redis 改造方案（待用户确认）

日期：2026-11-14。基线：`cdf362f`，开发分支：`codex/cli-dual-graph`。

本文是开工前的设计与验收约定；当前尚未实施、安装依赖或启动任何数据库服务。

## 1. 交付目标与约束

- 交付能够通过网页与 CLI 导入自己的文件、检索、问答、查看原文引用、更新和删除资料的单租户知识库。
- 正式运行使用 PostgreSQL + Qdrant server + Redis；保留手写余弦相似度、BM25、RRF、local/global 图检索与模型接口边界，不引入 LangChain、ChromaDB 或官方 LightRAG。
- 不按查询全量载入片段、向量和图谱；只读取候选原文、所需邻接关系及版本信息。允许显式的图谱导出和精确检索实验读取全库；这不属于正式查询路径。
- 使用自己的语料、独立标注与实测报告。模拟、词法离线模式和真实语义模型的结果分别报告。
- 本阶段不扩展多租户、SSO、计费、分布式高可用或界面风格重做；不将服务组合本身称为生产级或高可用证明。
- 在当前分支开发，不回退 Qdrant 原型、不删除旧引用、不合并主分支。统一验收后才合并 `main`。
- 代码改造授权不包含启动 WSL、Docker、数据库、后台常驻程序或修改 WSL 配置。真实集成验收前，必须单独确认运行位置、启动命令、资源限额和停止方案。
- 不购买远端服务、不自动启动本地模型。收费真实模型验收使用的供应商、题量和调用上限也应提前明确。

## 2. 系统边界

| 组件 | 保存及执行的内容 |
| --- | --- |
| PostgreSQL | 来源、不可变版本、片段原文与位置、实体、关系及原文证据、持久 BM25 词项与统计、导入/清理任务、会话、评测记录 |
| Qdrant server | 片段/实体/关系向量，记录 ID、来源 ID、版本 ID、模型指纹等过滤字段，执行有界候选召回 |
| Redis | 带模型和知识库版本标识的有限期缓存；待处理任务唤醒通知。任务可靠状态仍在 SQL 中 |
| Python 应用 | 手写算法、业务编排、模型请求、引用检查、CLI 和 Web API |
| 独立 Worker | 有界并发处理导入、重试与旧版本清理；按需启动，禁止导入模块即自动拉起后台进程 |

正式配置缺失时明确报错。不得偷偷切回 SQLite、模拟模型或本地 Qdrant。无服务测试使用显式测试适配器；不把这些结果称为真实 PostgreSQL/Qdrant/Redis 验收。

## 3. 数据发布与一致性

1. SQL 为一次导入登记唯一任务、新版本 ID 和预期来源修订。文件未变时按处理配置与内容散列跳过。
2. 在数据库写事务之外完成分块、抽取、证据校验和向量生成；保留现有输入限额与模型请求预算。
3. 使用包含新版本的稳定记录 ID 批量写入 Qdrant，并等待服务确认。同一任务重试采用幂等 ID。
4. 在 SQL 事务中校验任务租约及来源修订，发布原文、图记录和 BM25 词项，切换来源有效版本并递增知识库代数。
5. 只有有效版本进入查询和缓存。Qdrant 已写成功但 SQL 发布失败的向量属于不可见候选，后续补偿清理。
6. 删除先通过 SQL 使来源不可见，再以同事务登记的持久清理任务删除外部向量。失败重试；不删除整个集合重建。
7. 过期任务和删除前旧任务不能发布。任务租约控制重复执行，来源修订防止旧版本覆盖新版本。
8. 一次普通或多轮查询固定同一版本视图。旧版本清理必须等待该版本的有界查询租约释放或到期；查询到期应明确失败，不能跨版本继续生成。不得用“延迟几秒清理”冒充快照保护。

PostgreSQL 和 Qdrant 没有共同的普通 SQL 事务。本方案提供的是 SQL 控制的逻辑可见性和可重试补偿，不宣称跨存储原子提交。版本过滤还需处理无效候选占满召回窗口的情况：过滤有效版本或有限补召回，并在轨迹中记录候选丢弃与截断。

## 4. 检索与手写算法

- `vector`：Qdrant 对片段向量召回候选，SQL 按 ID 读取有效版本原文。
- `keyword`：写入时持久化词项、词频和长度；查询通过词项索引取候选并应用自己的 BM25 公式。不得查询时重新建立全库 BM25。
- `hybrid`：向量 + BM25，继续使用自己的 RRF。
- `local`：实体名称/向量定位，使用 SQL 索引查询有限的一跳邻接关系和原文证据。
- `global`：关系/主题向量定位，补充有限端点及来源证据；不虚称存在社区发现与社区摘要。
- `hybrid_graph`：四通道融合，保留来源覆盖分配、可选重排、上下文长度限制与引用绑定。
- 保留显式精确检索实验模式：使用自己的余弦相似度作为小规模基准，对比 Qdrant 向量候选覆盖、耗时和参数影响。正式召回属于 Qdrant 索引检索，不能称为纯手写 HNSW。
- 每个通道设置候选与图扩展预算，记录阶段耗时、模型/缓存调用、版本、候选数和最终引用。图谱导出与全量基准不默认执行。

## 5. 缓存与后台任务

- 缓存键包含：知识库有效代数、模型与提示配置、问题、检索模式、top-k、阈值、重排参数；多轮回答同时包含实际参与的有限历史。
- 文档更新/删除后旧缓存不再适用；缓存命中仍核对当前有效代数。缓存有 TTL 和值大小限制。
- Redis 不可用时缓存跳过并记录降级；不得把故障当空知识库，也不能继续返回无法核对版本的缓存。
- SQL 保存任务状态、尝试次数、可执行时间、租约令牌和到期时间。Redis 只负责通知；丢通知后 SQL 扫描仍能找回任务。
- 重试有次数与退避上限。Worker 停止、租约过期、重复投递、永久失败与清理积压都可观察。
- 默认保守配置：一个 Worker、导入任务并发 1、小连接池；模型请求保持当前超时、有限重试和限流。

## 6. Web、CLI 与现有数据

- CLI 与 FastAPI 使用同一新服务层，统一六种检索模式、错误语义、来源、修订和检索轨迹。
- 保留现有十个 CLI 命令：`ingest`、`sync`、`query`、`search`、`agentic-query`、`list`、`delete`、`graph`、`doctor`、`eval`。同步目录仍然只有显式 `--prune` 才删除消失来源，任意文件处理失败时不执行清理。
- 保留 CLI `--json` 的单一结构化 stdout 与非零错误退出码。`doctor` 诊断配置及已配置服务，但不能安装、启动或重启服务；会触发模型调用的在线检查必须显式选择。
- 网页支持上传进度、导入任务结果、资料列表、删除、普通/有界多轮问答、会话历史与引用展开，不引入新的前端框架。
- 不再启动时自动扫描样例文件，也不在缺证据时改用通用知识生成答案。旧网页 URL 导入入口需明确停用或移除，与新服务“显式本地文件导入”的边界一致。
- 会话与消息迁到 PostgreSQL；历史是对话上下文，不自动当作可信知识来源。限制历史长度并保证同一会话消息顺序。
- 上传文件使用生成的安全路径与稳定来源标识，校验大小、格式和提取限额；模型调用失败不损坏已发布知识。
- 回答在引用校验完成后发布。可以发送真实阶段进度，但不以切分最终字符串假装模型 token 流；未通过引用检查的内容不能先流出给用户。
- 现有 SQLite 数据保留原文件。提供显式迁移/重建操作与报告，不自动覆盖旧库；模型指纹或向量维度不兼容时要求重建。

## 8. 自有评测

- 原有指标保留并明确口径；正式标签使用稳定来源 ID，解决不同目录同名文件误匹配。
- 检索报告包含来源 Hit@k、Recall@k、Precision@k、MRR、关系端点实体召回、无答案题零召回率及各项计分题数；MRR 的来源去重口径与报告版本明确记录。
- 耗时报告分离：数据库候选读取、向量服务、关键词/图检索、融合/重排、答案生成和端到端时间。分别记录冷/热缓存，真实模型与模拟模型，不用命中缓存的实验冒充冷启动对照。
- 评测六种模式、重排开关、有界多轮，并提供 Qdrant 相对精确余弦基准的向量候选 Recall@k；不混同业务来源召回。
- 独立编写至少 40 条中文/中英混合标注题，覆盖单文件事实、跨文件、改写、实体关系、冲突和无答案。资料与题集同版本保存，调参题与最终验收题分开。
- 回答级验收逐题记录事实正确性、答案完整性、逐条引用支持、冲突处理与正确拒答。自动引用编号检查只代表结构有效，字词命中只代表词法覆盖，不能冒充语义事实正确率。
- 不复用参考项目成绩，不写无实测依据的提升百分比。真实模型结果保存模型、参数、语料散列、题集版本、配置、调用统计、环境与原始逐题记录。

## 9. 实施顺序

1. 固化当前基线与验收题，抽出存储/向量/缓存边界，先写能证明回归的失败测试。
2. PostgreSQL schema/迁移、版本发布和持久 BM25，保留显式的测试/精确基准适配器。
3. Qdrant 三类向量候选、图邻接查询、有界融合，消除正式路径全库加载。
4. Redis 版本化缓存、SQL 任务、Worker、重试和清理补偿，验证故障行为。
5. 统一 CLI/Web、会话与文件管理，提供旧数据迁移/重建入口。
6. 完成无需常驻数据库的自动化检查与代码审查，准备真实验收命令。
7. 单独确认部署位置与资源预算后，启动真实服务，执行数据迁移、端到端和故障验收，采集资源及性能数据。
8. 完成自己的评测、架构说明与面试材料，依据全部证据统一验收后合并 `main`。

上述步骤是同一目标的顺序分解，不以步骤 6 的模拟测试代替步骤 7 的真实验收。

## 10. 统一验收门槛

| 要求 | 必须取得的证据 |
| --- | --- |
| 算法正确 | 手算小样本与现有回归通过；新增行为先失败后通过，不靠同实现计算预期值 |
| 真正使用服务 | PostgreSQL/Qdrant/Redis 的真实连接、写入、读取、重启后持久化记录；模拟测试不能替代 |
| 日常可用 | 网页/CLI 完成导入、查询、跨文件问答、引用查看、更新、删除与会话恢复的端到端记录 |
| 原有 CLI 能力 | 十个命令的进程级验证；目录同步的 opt-in 清理与失败保护；JSON stdout、错误退出码、图谱导出和无副作用诊断 |
| 不全库加载 | 正式检索测试禁止调用全库 `records()`；按候选读取，查询记录与不同规模下的读取量/内存实测 |
| 更新一致 | 导入失败旧版本可用；更新中查询保持同一视图；过期任务无法发布；孤儿向量不进入回答 |
| 删除与缓存 | 删除提交后新查询不返回旧内容；缓存失效正确；Qdrant 清理失败可重试 |
| 任务恢复 | Redis 丢通知/断开、Worker 退出和重复领取情况下，任务可恢复且不会发布错误版本 |
| 检索质量 | 标注集逐题结果与模式消融报告；可答题空结果及无答案错误召回逐条解释，基线下降必须修复或明确接受后才能验收 |
| 回答质量 | 固定验收题无无效引用、无已删除/失效来源；人工事实与引用支持审阅有明确结果，不能仅靠合法编号判定通过 |
| 资源可控 | 用户批准的部署和启动方式；启动前后/空闲/查询时的内存观测；停止后进程与资源复核 |
| 可复现 | 完整配置样例、schema 迁移、命令、题集与原始报告；无密钥、私人资料或虚构指标进入仓库 |
| 主分支交付 | 所有必需检查与真实验收通过、问题处置完成后，才能合并 `main`；不提前清理历史分支/标签 |

检索、生成耗时与内存的数值目标需要依据用户批准的运行硬件、模型和实际语料规模确定，先记录基线再约定；不提前保证某个毫秒数或准确率。基础服务资源限制不是全系统总内存上限，还需观察应用、Worker、操作系统缓存和任何本地模型。
